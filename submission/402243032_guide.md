## PyCharm و خطای SDK

پروژه را با Open روی همین پوشهٔ `secure_video_steam-main` باز کنید. خطای ثبت‌شده در لاگ PyCharm مربوط به مرحلهٔ ایجاد خودکار SDK بوده است. مفسر فعلی Python 3.12.4 و محیط `venv` سالم‌اند و بسته‌های مورد نیاز داخل همان محیط نصب شده‌اند؛ آزمون‌ها با همین مفسر اجرا شده‌اند.

اگر هشدار قبلی هنوز دیده می‌شود، یک بار پروژه را ببندید و دوباره باز کنید. در PyCharm 2024.2 از `File > Settings > Project: secure_video_steam-main > Python Interpreter`، مفسر `Python 3.12 (secure_video_steam-main)` را انتخاب کنید. مسیر مفسر باید به `venv\Scripts\python.exe` در همین پروژه ختم شود. در صورت نیاز `Add Interpreter > Add Local Interpreter > Existing` را بزنید و همین فایل را معرفی کنید؛ محیط را پاک نکنید.

Run Configuration با نام `Video server` آماده است: آن را از فهرست بالای PyCharm انتخاب و Run کنید. سپس [صفحهٔ پخش](http://127.0.0.1:8000) را در Chrome یا Edge باز کنید، Nature را انتخاب کنید و در صورت نیاز Play را بزنید. فایل `run_video.cmd` نیز همین سرور را اجرا می‌کند.

دستورهای PowerShell از ریشهٔ پروژه:

```powershell
.\venv\Scripts\python.exe -m stream_server --port 8000
.\venv\Scripts\python.exe -m unittest discover -s tests -v
.\venv\Scripts\python.exe -m tools.evaluate
```

آزمون‌های JavaScript به Node.js نیاز دارند. اگر در ترمینال PyCharm فرمان `node --version` شناخته نشد، Node.js نسخهٔ LTS را از [سایت رسمی](https://nodejs.org/) نصب و PyCharm را دوباره باز کنید. خود برنامهٔ پخش به نصب Node.js نیاز ندارد.

اگر در آینده نصب دوبارهٔ بسته‌ها لازم شد، به علت مسیر فارسی، UTF-8 را فعال کنید:

```powershell
$env:PYTHONUTF8='1'
$env:PYTHONIOENCODING='utf-8'
.\venv\Scripts\python.exe -m pip install -r requirements.txt
```

## GitHub

Fork شما موجود است: [Mahdi-Arjmandnia/secure_video_steam](https://github.com/Mahdi-Arjmandnia/secure_video_steam).
اتصال SDK و اتصال GitHub دو تنظیم جداگانه هستند؛ ورود GitHub برای اجرای پایتون لازم نیست.
تاریخچهٔ Fork به پروژهٔ محلی وصل شده و `origin` همان نشانی بالا است. تغییرها عمداً برای بازبینی Commit نشده‌اند و هنوز Push نشده‌اند.

در PyCharm:

1. `Settings > Version Control > Git` را بررسی کنید و مسیر Git را با Test تأیید کنید. اگر خودکار تشخیص داده نشد، در این دستگاه این فایل موجود و آزمایش شده است: `C:\Users\IT\.cache\codex-runtimes\codex-primary-runtime\dependencies\native\git\cmd\git.exe`. آن را در Path to Git executable انتخاب کنید. اگر بعداً Codex حذف شد، Git for Windows را نصب و مسیر Git جدید را معرفی کنید.
2. برای ورود راحت، در `Settings > Version Control > GitHub` حساب خودتان را با `Log In via GitHub` اضافه کنید؛ ورود در مرورگر را خودتان تکمیل کنید. اتصال حساب برای اجرای برنامه لازم نیست.
3. با `Ctrl+K` فایل‌های تغییرکرده و پوشهٔ `submission` را بررسی کنید و Commit بزنید؛ پیام پیشنهادی: `Complete eight stream cipher functions and practical report`.
4. با `Ctrl+Shift+K` تغییرها را به `origin/main` بفرستید. اولین Push ممکن است ورود در مرورگر بخواهد.
5. صفحهٔ Fork را باز کنید و ببینید کد سه فایل و گزارش جدید واقعاً روی GitHub قرار گرفته‌اند. لینک Fork داخل گزارش آمده است؛ موجودبودن Fork به‌تنهایی به معنی آپلود کد تکمیل‌شده نیست.

برای روش ترمینال:

```powershell
git status
git add stream_cipher.py cipher_variants.py web/cipher.js .gitignore README_FA.md run_video.cmd submission
git commit -m "Complete stream cipher practical assignment"
git push origin main
```
